# badge-menu patch

Custom **badge-menu firmware** (LVGL touch UI + BLE tools) for the JieLi AC707N/BR35, kept as a
patch on top of the **vanilla** JieLi watch SDK. The SDK itself is **not** stored here — it is the
git submodule at `tools/community-re/jieli-sdks/e_badge_707_sdk_200` (JieLi's GitLab, pinned at the
vanilla `main` commit `d016768`, clonable anonymously). This keeps JieLi's SDK out of this repo
while making the custom work reproducible.

## Files

- `badge-menu.patch` — the source delta (49 text files, `git diff` format, paths rooted at the SDK
  repo root: `SDK/…`, plus `README.md` and `docs/BUILD.md`). Text sources only. Of its ~15.5 k
  added lines, **~10.7 k are two embedded image headers** (`gatito_logo_rgb565.h`,
  `lock_wallpaper.h`); the actual code delta is ~4.8 k lines, the bulk of it
  `SDK/apps/common/ui/lvgl_v8/lvgl_main.c` (+1358: menu, spoofer, mouse, scanner),
  `qix_ota_server.c` (+577) and `qix_raw_flash.c` (+351).

## Build

**Use the scripts** — they handle the pieces the patch cannot carry (see below):

```sh
scripts/setup-badge-build.sh          # once
scripts/build-badge-fw.sh --ota       # each build
```

Full guide, provenance of every downloaded piece, and a troubleshooting table:
**[docs/build-badge-firmware.md](../../docs/build-badge-firmware.md)**.

By hand, the same thing:

```sh
# 1. Get the vanilla SDK (anonymous clone, ~1.1 GB — no JieLi account needed)
git submodule update --init --depth 1 tools/community-re/jieli-sdks/e_badge_707_sdk_200
SDK=tools/community-re/jieli-sdks/e_badge_707_sdk_200

# 2. Apply the badge patch onto the vanilla SDK
git -C "$SDK" apply "$PWD/patches/badge/badge-menu.patch"

# 3. The two pieces the patch cannot carry (see below)
#    - SDK/tools/linux/*                 -> scripts/setup-badge-build.sh
#    - SDK/cpu/br35/tools/download/watch/chipkey_9847.bin

# 4. Build (needs the pi32v2 toolchain on PATH and a high open-file limit)
export PATH="/opt/jieli/pi32v2/bin:$PATH"
ulimit -n 65536
( cd "$SDK/SDK" && make clean && BADGE_CHIPKEY=9847 make MENU=1 )
# -> SDK/cpu/br35/tools/app.bin  +  SDK/output/{update.ufw,jl_isd.fw,jl_isd.bin}
```

## Not carried by the text patch

The patch is text-only. These pieces of the setup are **not** in it and are installed by
`scripts/setup-badge-build.sh`:

- `SDK/tools/linux/*` — the 7 native Linux post-build tools (`isd_download`, `ufw_maker`,
  `fw_add`, `packres`, `json_to_res`, `fat_comm`, `remove_tailing_zeros`). They are a separate
  public JieLi download (`pkgman.jieliapp.com/s/linux-postbuild`); the SDK ships only the Windows
  `.exe` equivalents. Needed for the **USB** images only — the BLE OTA path needs just `app.bin`.
- `SDK/cpu/br35/tools/download/watch/chipkey_9847.bin` — the device flashing key, kept in
  `tools/chipkey/`. Without it the build emits a **keyless** image.
- Generated artifacts (`config.dat`, `data.bin`, `text.bin`, `download.sh`, `fileList.dumy`, …) are
  regenerated by the build and are intentionally **excluded**.

Vendor `.a` libraries are used **as shipped** — the build needs no binary library patch.

## Regenerating the patch

From the working SDK tree (vanilla + your changes), at the SDK repo root:

```sh
git add -A -- ':!SDK/tools/linux' ':!output' ':!SDK/output'
git diff --cached -- ':!*.a' ':!*.bin' ':!SDK/tools/linux/**' ':!*.cbp' ':!**/*.bat' \
  ':!**/json.txt' ':!SDK/build/fileList.dumy' ':!output/**' ':!SDK/output/**' \
  > ../../../../patches/badge/badge-menu.patch
git reset
```
